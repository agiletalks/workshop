# 測試案例：講師語音重點筆記功能

**版本**：v0.1  
**分支**：`feature/instructor-voice-notes`  
**建立日期**：2026-09-23  
**對應需求**：[VOICE_NOTE_REQUIREMENTS.md](file:///C:/Antigravity/workshop/ai-arm/VOICE_NOTE_REQUIREMENTS.md)

## 測試環境前置條件

- 瀏覽器：**Google Chrome 最新版**（Web Speech API 必要）
- 身分切換：測試時需可切換「講師」/「學員」身分
- 麥克風：本機可用麥克風裝置
- API Key：`localStorage.setItem('GEMINI_API_KEY', '<your-key>')` 已設定
- Firebase：連線至測試用 class（建議使用獨立測試班級 `classId: test-voice-note`）

## TC-04：停止錄音與 AI 摘要

### TC-04-1：正常停止產生摘要
| 欄位 | 內容 |
|---|---|
| **對應 AC** | AC-03-1、AC-03-3 |
| **前置條件** | 錄音中；已說了約 30 秒的教學內容（含具體知識點） |
| **測試步驟** | 1. 點擊「停止」按鈕 |
| **預期結果** | 1. 顯示「AI 整理中...」spinner；2. 約 3~8 秒後，顯示摘要卡片（含 overviewSummary + takeaways 列表） |
| **Pass 標準** | 摘要卡片顯示；`overviewSummary` 非空；`takeaways` 至少 2 項 |

### TC-04-2：摘要卡片「套用到筆記區」功能
| 欄位 | 內容 |
|---|---|
| **對應 AC** | AC-03-4 |
| **前置條件** | 摘要卡片已顯示；學員筆記區（`#team-memo-input`）有既有內容「第1組：...」 |
| **測試步驟** | 1. 點擊摘要卡片中的「✅ 套用到筆記區」|
| **預期結果** | `#team-memo-input` 的內容在**末尾**追加摘要文字（不覆蓋原有內容） |
| **Pass 標準** | 原有內容保留；摘要追加在底部；並觸發 Firestore 自動同步 |

### TC-04-3：摘要卡片「重新整理」功能
| 欄位 | 內容 |
|---|---|
| **對應 AC** | AC-03-5 |
| **前置條件** | 摘要卡片已顯示 |
| **測試步驟** | 1. 點擊「✏️ 重新整理」|
| **預期結果** | 重新呼叫 AI（原始逐字稿不變）；顯示新的摘要結果 |
| **Pass 標準** | 摘要內容可能略有不同；原始逐字稿不被清除 |

### TC-04-4：逐字稿為空時的處理
| 欄位 | 內容 |
|---|---|
| **對應 AC** | AC-03-7 |
| **前置條件** | 點擊錄音後，**未說任何話**，直接點停止（錄音 < 3 秒） |
| **測試步驟** | 1. 錄音啟動 → 2. 立即點「停止」|
| **預期結果** | 顯示提示訊息「未偵測到語音，請重新錄音」；不呼叫 AI API |
| **Pass 標準** | 不出現 spinner；不出現摘要卡片；顯示適當提示 |

### TC-04-5：AI API 呼叫逾時的處理
| 欄位 | 內容 |
|---|---|
| **對應 AC** | AC-03-2 |
| **前置條件** | 停止錄音後；模擬 API 逾時（可透過 DevTools 設定 Slow 3G 或手動設定錯誤 Key）|
| **測試步驟** | 1. 停止錄音 → 等待 AI 回應 |
| **預期結果** | 15 秒後顯示錯誤提示「AI 整理失敗，原始逐字稿已保留」；顯示原始逐字稿供手動複製 |
| **Pass 標準** | 超時後不卡死；顯示 fallback 逐字稿；使用者可重試 |
