## 模組一：門禁安全性（去暗示化 + 連續失敗安全鎖定）

### TC-SEC-01：門禁畫面去範例化與去暗示性查核
- **前置條件**：以無痕視窗或清除 localStorage 後開啟 `http://localhost:5000/workshop/ai-arm/`。
- **操作步驟**：
  1. 觀察「AI-ARM 課程專屬報到處」畫面。
  2. 檢查欄位「1. 班級專屬代碼 (Class Code)」。
- **預期結果**：
  - [ ] 標籤旁**不得**出現 `例：2026-cathay` 或任何特定公司/年份的命名規律暗示。
  - [ ] 輸入框之 Placeholder 應為中性的「`請輸入講師公布之專屬代碼`」，絕無任何具體代碼範例。
  - [ ] 未輸入代碼直接提交時，錯誤提示應為「`請輸入講師公布之專屬班級代碼`」，無任何暗示字樣。

### TC-SEC-02：連續登入失敗累計與鎖定觸發
- **前置條件**：處於門禁畫面，localStorage 中無既有鎖定狀態。
- **操作步驟**：
  1. 輸入姓名：`Tester`。
  2. 輸入不存在之班級代碼：`fake-code-999`。
  3. 連續點擊「🚀 完成報到，進入第 1 頁講義」按鈕 5 次。
- **預期結果**：
  - [ ] 第 1 次至第 4 次失敗時，提示訊息顯示「查無班級代碼【fake-code-999】，請確認後重新輸入（剩餘嘗試次數：N 次）」。
  - [ ] 第 5 次提交失敗時，系統**立即觸發安全鎖定 3 分鐘（180 秒）**。
  - [ ] 按鈕立即變更為「`⏳ 安全鎖定中 (03:00)`」（或從 `02:59` 開始動態倒數）。
  - [ ] 輸入框（代碼與姓名）與送出按鈕全部被設定為 `disabled` 反灰狀態，無法繼續送出。

### TC-SEC-03：鎖定期間 UI 動態倒數計時
- **前置條件**：系統已進入安全鎖定狀態。
- **操作步驟**：
  1. 停留在鎖定畫面觀察 5~10 秒。
- **預期結果**：
  - [ ] 錯誤提示區顯示：「`⚠️ 連續嘗試失敗達上限，安全鎖定中，請等待 mm:ss 後再試`」。
  - [ ] 時間每秒動態遞減（例如 02:55 -> 02:54 -> 02:53 ...）。
  - [ ] 送出按鈕文字同步每秒即時更新為對應倒數秒數。

### TC-SEC-04：F5 重新整理與分頁重開防繞過
- **前置條件**：系統處於安全鎖定狀態（剩餘約 2 分鐘）。
- **操作步驟**：
  1. 按鍵盤 F5 重新整理分頁（或關閉分頁重新開啟相同網址）。
- **預期結果**：
  - [ ] 重新載入後，門禁畫面**依然維持鎖定狀態**，無法透過重新整理頁面破解。
  - [ ] 倒數計時器根據原本的截止時間戳記持續倒數（秒數正確延續，未被重置回 3 分鐘）。
  - [ ] 輸入框與按鈕持續維持 disabled 禁用狀態。

### TC-SEC-05：鎖定時間歸零自動解鎖
- **前置條件**：系統處於安全鎖定狀態，等候或調整本機 localStorage `ai_arm_gate_lock_until` 至即將過期。
- **操作步驟**：
  1. 等待倒數計時抵達 `00:00`。
- **預期結果**：
  - [ ] 倒數歸零時，系統自動解除鎖定。
  - [ ] 代碼與姓名輸入框恢復可輸入狀態，游標自動聚焦至代碼輸入框。
  - [ ] 送出按鈕恢復為可點擊之金色樣式「🚀 完成報到，進入第 1 頁講義」。
  - [ ] 錯誤訊息自動隱藏。

### TC-SEC-06：正常登入後失敗計數清空
- **前置條件**：曾有 1~4 次失敗嘗試紀錄，但尚未鎖定。
- **操作步驟**：
  1. 輸入正確的班級代碼（如有效班級）與姓名、組別。
  2. 點擊提交完成報到。
- **預期結果**：
  - [ ] 成功進入講義 P01。
  - [ ] 本地 `localStorage` 中的 `ai_arm_gate_fail_count` 與 `ai_arm_gate_lock_until` 被完全清除重置。

## 模組二：手機端筆記滾動體驗（手機專屬雙頁籤切換）

### TC-MOB-01：手機版專屬頁籤列顯示與切換
- **前置條件**：使用 DevTools 開啟行動裝置模擬（寬度設為 390px，高度 844px），登入有效班級。
- **操作步驟**：
  1. 觀察講義畫面頂部（導覽列下方、主工作區上方）。
  2. 觀察是否存在「`[ 投影片 ]` ｜ `[ 小組筆記與附件 ]`」頁籤。
  3. 點擊「`[ 小組筆記與附件 ]`」，再點擊「`[ 投影片 ]`」。
- **預期結果**：
  - [ ] 手機版頂部正確出現專屬頁籤切換列。
  - [ ] 點擊「小組筆記與附件」時，按鈕呈現選中樣式（琥珀金底黑字），下方投影片區收合，筆記區滿版展示。
  - [ ] 點擊「投影片」時，按鈕呈現選中樣式，投影片區完整展示，筆記區收合。

### TC-MOB-02：手機筆記區滿版延展與無嵌套死鎖滾動
- **前置條件**：手機模式切換至「小組筆記與附件」分頁。
- **操作步驟**：
  1. 點擊隨堂筆記輸入框（textarea）。
  2. 在筆記框內輸入 15 行以上的長文字內容。
  3. 使用手機觸控手勢（模擬 Touch 滑動）向下滑動頁面。
- **預期結果**：
  - [ ] 筆記區域擁有完整的垂直滾動空間，滑動時流暢無卡頓。
  - [ ] 絕不會發生「滑動被外層 body/main 吃掉鎖死」或「手指按在 textarea 上無法滑動到底部」的窘境。
  - [ ] 頁面可一路順暢滑動至最下方的「小組實作附件」區塊。

### TC-MOB-03：小組附件區露出與上傳按鈕可點擊性
- **前置條件**：手機模式，停留在筆記頁籤並滑動至底部。
- **操作步驟**：
  1. 觀察「小組實作附件」面板與清單。
  2. 點擊「上傳附件」按鈕。
- **預期結果**：
  - [ ] 附件管理面板完整露出，無任何被螢幕邊緣或虛擬工具列遮蔽情況。
  - [ ] 點擊「上傳附件」可正常喚起作業系統的檔案選取對話框。
  - [ ] 上傳後之附件卡片清單可正常展開並支援點擊預覽/下載。

### TC-MOB-04：桌機版 (≥ 768px) 版面零影響回歸
- **前置條件**：將視窗寬度拉大至 1024px 以上（桌機/筆電尺寸）。
- **操作步驟**：
  1. 觀察頁面佈局。
  2. 點擊頂部的「劇院模式」按鈕。
- **預期結果**：
  - [ ] 手機專屬頁籤列自動隱藏（`md:hidden`）。
  - [ ] 預設工作台模式維持經典「左側投影片、右側隨堂筆記」左右雙欄 1:1 黃金比例。
  - [ ] 切換劇院模式與雙欄模式正常運作，無破版或樣式走樣。

## 模組三：全班跨組即時表情微互動（全場跨頁同步）

### TC-REA-01：班級頻道動態綁定正確性
- **前置條件**：使用固定入口 `http://localhost:5000/workshop/ai-arm/` 開啟分頁。
- **操作步驟**：
  1. 在門禁畫面輸入班級代碼（例如 `qa-retest-0920-b`），報到進入。
  2. 開啟 Console 查看網路活動或 Firestore 監聽通道。
- **預期結果**：
  - [ ] 表情監聽頻道正確綁定至 `ai_arm_qa-retest-0920-b_reaction_latest`，不再殘留或誤綁空代碼頻道。

### TC-REA-02：跨頁即時表情廣播同步
- **前置條件**：開啟兩個分頁（分頁 A 與分頁 B），兩端進入相同班級。
- **操作步驟**：
  1. 分頁 A 翻至第 1 頁（P01）。
  2. 分頁 B 翻至第 5 頁（P05）。
  3. 在分頁 A 底部的表情列點擊愛心「❤️」或煙火「🎆」。
- **預期結果**：
  - [ ] 分頁 A 本地立即綻放表情粒子動畫（向上飄散並旋轉）。
  - [ ] **關鍵驗證**：分頁 B（處於不同的第 5 頁）**在 1 秒內同步噴發相同之表情粒子**，不再因「頁碼不同」被丟棄！

### TC-REA-03：跨組與不同身分即時表情廣播
- **前置條件**：
  - 分頁 A 身分：第 1 組學員。
  - 分頁 B 身分：第 2 組學員（或使用手機與電腦兩台裝置同時開啟）。
- **操作步驟**：
  1. 分頁 A 點擊大拇指「👍」或大腦「🤯」。
- **預期結果**：
  - [ ] 分頁 B 同時看到螢幕上飄出對應的表情粒子，實現真正的全班跨組同歡。

### TC-REA-04：Unique Reaction ID 防重與時鐘飄移容錯
- **操作步驟**：
  1. 觀察發送與接收之資料結構。
- **預期結果**：
  - [ ] 每次點擊發送皆帶有唯一 `reactionId`。
  - [ ] 接收端收到後僅呈現一次，不會造成重複觸發。
  - [ ] 跨裝置即使系統時間存在微小秒差（> 3 秒），表情粒子依然能正常展示，不受本機與伺服器時間飄移影響。
